# 三国竖屏塔防 — 后续开发计划（2026-11-25）

> **目标**：在现有 Cocos 3.8.7 客户端 + NestJS 后端上，优先稳住玩法与测试基线、收口发布前安全开关，再渐进做货币权威化与商业化收口。不盲加大型系统，不擅自改数值经济或美术方向。  
> **架构**：客户端离线优先 + 整档同步；服务端战斗回放校验与 `profile-guard` 截断；测试期客户端放开选关/武将，服务端开战仍校验关卡锁。  
> **技术栈**：Cocos Creator 3.8.7、TypeScript、Node 原生 `node:test`、NestJS + Prisma + Redis。  
> **本计划约束**：只本地 commit；禁止 push / PR / remote 修改 / reset / clean / stash / force / amend / 跳 hooks / `git add .`；不安装依赖、不生产迁移；保护用户现有未提交变更（`settings/v2/packages/cocos-service.json`、`engine.json`、未跟踪 `sanguo/`）。

## 3. 任务详情

### T01 — 测试基线可靠性（本轮实施）

- **现状源码证据**：`tests/run_all.test.mjs` 测试 `#5` 在读取 `build/wechatgame/src/settings.json` 时 ENOENT；`build-wechat.json` 与 `assets/scenes/Main.scene.meta` 的 UUID 校验本可不依赖构建产物。
- **依赖**：无。
- **改动边界**：仅 `tests/run_all.test.mjs`（及本任务完成记录）；不改玩法/数值/美术。
- **验收**：
  1. 无 `build/wechatgame` 时 `npm test` **全部通过**（构建产物相关断言为 **skip**，并打印明确原因）。
  2. 源码侧 `build-wechat.json` ↔ `Main.scene.meta` UUID 一致性**始终执行**。
  3. 若存在构建产物，则仍校验 `settings.json` ↔ `main/config.json` 启动场景。
- **需用户材料**：无。若要验证 skip 分支以外的构建校验，需用户在 Cocos 中导出微信工程。
- **docs / commit 流程**：实现并 `npm test` 通过 → 写 `docs/T01_任务完成记录.md` → **仅** add 本任务文件 → 独立 commit。
